# 麦麦饱饱盘产品约定

饭点用一次短流程决定一顿套餐。默认单人，可切换人数；每个人的食量与人均预算决定整顿搭配。

## 流程

1. 选择门店；默认 1 人，可选 2–4 人。
2. 选择每个人的 5/7/9 分食量、人均预算，手动勾选前两天主食，或在雷达读历史后主动导入可识别主食，作为本次避开条件。
3. 获取服务器时间、可领取券、个人券包、当前门店/渠道的可用范围、活动日历，展示优惠信息表。券校验启用状态、期限、商品编码；能关联日历规则时校验星期和时段。
4. 从在售套餐生成足够人数的完整搭配，包括随心配、三件套餐和分享餐。已持有且验证适用的券参与核价；未领取券展示领取条件。
5. 对当前人数/食量的所有非重复模板比较无券与适用券的官方报价，再按整顿预算过滤。不能因无券基准价超预算就提前丢弃可能由持有券降价的套餐。自动活动以官方报价为准，不按宣传价格重复扣减。
6. 圆盘只包含成功核价且满足条件的完整餐单；揭晓显示套餐名、全部内容/数量、总价、人均价和剩余预算。
7. 再转排除本轮已揭晓餐单。人数、预算、份量、门店、餐品或券状态变化后，旧结果和旧核价失效。

## 默认与份量

默认 1 人、7 分、人均 30 元；切换人数保持人均预算，并更新整顿上限。多人暂用同一食量档位，每个人至少有一份主餐；小食拼盘不能自动当成完整多人套餐。

5 分可用随心配，7 分可用三件套餐，9 分可用含主餐、饮品、麦乐鸡和派的双份随心配。价格不作为份量指标，份量也不等于营养建议或饱腹保证。

## 不重样与成员

历史套餐应展开子项并按主食编码匹配。同款主食换套餐仍算重复；可乐或薯条相同不排除整餐。

用户连接后可主动读取历史订单；昨天和前天按官方时间及中国时区计算，已完成套餐展开子项，按已知商品编码识别主食。点击导入才加入本次避开项，保留原有手动选择。接口没有分页参数，未返回或编码不明的部分需要手动补充，不能声称已覆盖两天。

历史记录与本次避开项仅在本页内存保留，多人按全桌共同避开。发起人的个人订单不能代表所有成员；各自食量和忌口属于后续扩展。虚构雷达示例清楚标注来源，不能导入最近主食。AI 另有用户选择保存的明确口味反馈，不能当作消费记录。

## 麦当劳雷达

与套餐圆盘并列的历史入口：全年 / 近 12 周、年份切换、每天的完成订单数、点击日期的套餐明细、当前范围有记录日期和常点餐品。只统计已完成 / 已评价，排除取消、待支付、无效时间与未来记录。常点餐品按包含该餐品的完成订单数计算，不推算实际个人食量。

全年是展示范围，并不保证历史完整；无记录日期标为“未返回记录”，未来日期禁用。不展示未经确认单位的历史金额，不保存个人订单，不以连续打卡鼓励增加消费。数据与验证边界见 [order-radar.md](order-radar.md)。

## 凭证与选店

用户可自行勾选“在这个浏览器长期记住凭证”，只保存 Token 和上次门店身份到本机，不跨设备同步。刷新或重开自动连接，并向 MCP 重新确认上次门店营业情况；取消勾选删除长期记录但保留当前连接，主动断开同时删除记录和本页数据。个人订单、地址簿、券包和旧报价不持久保存。

位置可直接输入城市和地址 / 地标，也可主动读取麦当劳已存地址并选择搜索位置。接口只有城市和关键词入参，没有经纬度入参；门店顺序使用官方返回，不宣称 GPS 距离最近。营业状态和时段完整展示，未知状态不当作营业中，换店立即清空旧报价。

## 实现状态

2.3.0 加入 AI 饭搭子：DeepSeek V4.1 Flash、推荐与优化两个可选 Agent、三种风格 / 目标、可编辑个人与 Agent prompt、显式反馈的本机长期记忆，以及城市天气、月份、核验假期和调休情境。推荐只在已核价候选内选择；原转盘保持等概率，本地推荐可独立使用。密钥保存和口味记忆是两个 opt-in，刷新恢复配置但不自动请求 AI。详细约定见 [meal-agents.md](meal-agents.md)，最新验证见 [validation.md](validation.md)。

已实现纯前端扩展原型与静态体验页：暖色卡片、人数/食量切换、预算快捷选择、优惠口袋、账号与门店面板、全部领券确认、核价进度、完整餐单比较与转盘结果。先点“算好价格，生成转盘”，成功后才能揭晓；条件变化或报价失效需重新计算。页面直接使用用户自行输入的 Token，没有业务后端或开发者账号存储。

静态模式禁用 Token 输入与领券，所有价格、可领券和活动均标记为历史样本，雷达另有明确标注的虚构示例。扩展已由用户安装并复测连接成功；2.2.0 加入长期凭证保存和地址选点。2.3.0 已完成 69 项 JavaScript 测试，Chrome 实际验证了两种凭证重载恢复、实时核价与 DeepSeek 两轮推荐，并通过 GitHub 提供源码、扩展下载和静态体验；真实账号历史显示仍需复测。服务使用范围见 [frontend-architecture.md](frontend-architecture.md)，完整验证见 [validation.md](validation.md)。饭点提醒、局部换项和导出餐单卡待接入；目前可主动复制餐单文字。

“最佳”限于当前模板与已验证券的生成范围；每份餐单最多比较 64 个方案，发生截断、分页不完整、日历失败或核价失败时显示“最低已核验价”。轮盘保留预算内的不同餐单，每份先选自身的最低有效核价，再等概率揭晓。五分钟缓存上限会被券到期/日历时段结束提前截断，浏览器按服务返回的剩余时间判断，不依赖设备时钟。

零候选时说明当前条件没有可核价搭配，由用户调整；一个候选直接揭晓。选餐圆盘与官方积分抽奖无关。
