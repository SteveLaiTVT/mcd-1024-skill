# 麦当劳雷达

2.1.0 新增。连接用户自己的 MCP Token，点击“麦当劳雷达 → 读取我的历史”即可生成 GitHub 风格的日历热力图，不需要先选择门店。查询由用户动作触发，没有定时或后台读取。

## 展示与统计

- 全年和近 12 周切换，年份可选官方当前年、上一年及返回记录涉及的年份。
- 格子深浅表示该日已返回的完成订单数，4 笔及以上用最深色；点击回看时间、状态、门店名称、套餐及子项。方向键可浏览日期。
- 汇总只统计当前展示范围：完成订单、有记录日期、餐品种类，以及包含某餐品的订单数排行；数量不等于个人实际吃了多少餐。
- 只纳入已完成 / 已评价状态。订单 ID 去重；无效或未来时间排除。中国日期用于跨时区归日，无时区官方时间按 UTC+8 解析。

官方 `order-list({})` 没有分页或日期查询参数。全年只是日历范围，并不代表已取得全年记录。斜线格表示未返回记录，不能据此判断没吃过；未来浅灰格禁用。读取失败保留“未完成”状态，统计显示横线，不生成零订单报告。

## 和套餐圆盘联动

按官方时间定位昨天、前天，从完成订单的套餐子项中精确匹配已知主食编码。用户点击“把前两天主食加入避开项”后才合并到已有手动选择，并切回选餐页、清除旧报价；用户可增删后重新核价。无法识别或未返回的部分需要手动补充，多人用餐由发起人确认全桌是否共同避开。

“先看虚构示例”使用独立生成的虚构餐单，仅供观察热力图交互，页面明确标注来源，不能导入最近主食。真实读取不会混入示例数据。

## 数据留存

只读取官方时间和订单列表，不调用含地址、电话或支付数据的订单详情。订单 ID 仅在本次响应去重，之后删除；展示对象不含订单 ID、门店编码、渠道编码或原始金额。金额单位未确认，暂不展示消费额。

2.2.0 可自行选择在本机扩展长期保存 Token 和上次门店，刷新自动恢复连接；取消勾选或主动断开删除凭证。个人历史仍仅在应用页内存中处理，不上传开发者服务器、不写文件或浏览器存储、不进入公开数据集，断开、刷新、关闭即清除，恢复连接不会自动读取历史；断开后的旧查询返回也不能恢复数据。公共构建只含代码、公开套餐样本及明确标注的虚构雷达生成器。

## 验证边界

当前 48 项 JavaScript 测试通过，其中新增 7 项历史统计和 2 项雷达页面状态测试，覆盖完成状态、去重、跨时区、闰年、年度 / 12 周范围、精确最近两天、导入、失败与断开竞态。当前模块在 Node 环境真实读取到 10 笔完成订单、8 个有记录日期，生成 2026 年 53 周日历；前两天可识别主食为 0。

2.2.0 扩展与静态页已构建，Chrome 已重新加载到 2.2.0，并检查虚构示例的年度 / 近 12 周热力图、颜色图例、日期点击及餐单明细。旧版扩展真实连接已由用户复测成功；新版真实历史与长期凭证恢复仍需用户自己的 Token 验证。此处不把模拟 DOM 或 Node 调用当作浏览器像素证明。完整证据见 [validation.md](validation.md)。
