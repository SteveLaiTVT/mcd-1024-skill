# 麦当劳 MCP 实测笔记（修正版）

2026-10-10，以进程环境 `MCD_TOKEN` 连接官方 MCP。最新样本以 [manifest](../data/manifest.json) 为准。初始化材料中“24 个接口全部实测”“一半响应只能解析 Markdown”“只使用实时数据”不再作为当前产品说明。

## 响应结构

响应同时含 `content[].text` 和 `structuredContent`。活动日历、券包等在前者可能是展示文案，在后者有结构化业务数据；营养表的 `structuredContent.data` 仍为 `[N]{fields}:` 文本表。先取业务结构，再解析确实为文本的数据。

营养表有 160 行、158 个不同名称，小杯玉米杯与纯牛奶（盒装）存在重复名称。保留原记录并报告重复，不凭名称合并营养值，也不把名称匹配等同于商品编码匹配。

## 套餐数量

麦麦周末双人餐的小食轮次要求 2 件，已选中薯条和脆薯饼；后者 `isDefault=0` 但 `quantity=1`。饮品也有可乐与咖啡。只读取一个默认项会漏掉半份双人餐。

核价子项数量是每份套餐的数量；两份双人餐的外层 `quantity=2`，展开内容时才将子项乘 2。构造器校验轮次总数、每项上限与主餐覆盖人数。

有 `unselectedKey` 的特调值必须显式传入：选中用 `selectedKey`，未选中用 `unselectedKey`；必选组要满足 `minValues` / `maxValues`。

## 展示价与核价

菜单 `currentPrice` 是元的字符串，核价 `price` 为整数分。此前巨无霸四件套餐显示 32 元，默认搭配核价为 58.50 元，原因尚未查明。不能认定接口错误，也不能用较低展示价承诺成交。

当前样本加入 20 元、22.90 元单人套餐和 49.90 元双人分享餐等整单报价，数值只代表采样门店与时点。

## 优惠券

| 工具 | 用途 | 限制 |
|---|---|---|
| `available-coupons` | 当前账号可领取展示 | 无法直接定价 |
| `query-my-coupons` | 持有资产，最多 5 页、每页 200 | 持有不代表当前门店可用；同名不同 ID 是不同资产 |
| `query-store-coupons` | 门店/取餐方式适用券与商品映射 | 与卡包 ID 关联，按商品编码匹配 |
| `auto-bind-coupons` | 一键领取全部当前可领券 | 没有单张领取参数；领取后重新查询 |

## 活动信息表

`campaign-calendar` 带 `specifiedDate` 返回锚点日及最近前后有活动的日子，不是当月完整活动。10/10 当天 15 条、10/9 一条、10/11 两条，共 18 条，均为文章事件 `eventType=4`。标题在 `articleDto.title`，`activityTitle` 为空；价格字段均为字符串 `0`，这只是文章字段，不能算作免费餐。公共快照删除券标识、个人订阅和文章正文，见 [campaigns.json](../data/campaigns.json)。

日历券的 `weekdays` 为周日=1、周六=7；核销日期、全天标记或时间段分别判断。仅在官方券资产/规则码可关联时参与时间限制，不能从相似标题推导用券资格。

## 历史订单与雷达

`order-list` 的输入定义没有分页、日期或门店参数，仅返回 `data.list`。当前 JavaScript 客户端真实查询返回 10 笔完成订单、8 个有记录日期，不能据此恢复全年或保证覆盖前两天。记录包含 `orderProductList` 与 `comboItemList` 套餐子项；真实完成状态为中文 `订单已完成`，时间为无时区的 `YYYY-MM-DD HH:mm:ss`，按中国时区解释。已完成 / 已评价状态才进入日历，其余状态、无效时间、未来记录不计入。

订单 ID 仅用于本次响应去重，不进入统计对象或 DOM；门店编码、订单渠道编码和原始金额也不保留。`realTotalAmount` 实测为整数字符串，但单位未确认，不用于历史消费展示。常点餐品按含该餐品的订单数计数，套餐包装不与子项重复累计。

前两天按官方时间锚定昨天和前天，精确匹配公开菜单的已知主食编码。本次可识别类型为 0，导入按钮应禁用；不凭套餐名称猜测或把更早记录冒充最近两天。读历史仅由用户按钮触发，不调用 `query-order`，原始订单不进入文件、公开样本或构建产物。详见 [order-radar.md](order-radar.md)。

## 其他边界

- 华强北样本经纬度为 0，不能推广为所有门店都没有坐标。
- 普通多人点餐使用到店自取。企业团餐助餐接口前置条件不同，到店参数探测曾被 `610501` 拒绝。
- 派对时段工具名为 `query-party-store-date` / `query-party-store-session`。
- `query-promotions` 仅适用于企业团餐，不用于普通到店优惠查询。

## 前端协议与跨域检查

17:42 使用当前 JavaScript 客户端在 Node 环境完成初始化、官方时间与可领券查询，返回 6 条展示。该验证使用环境 Token，只请求官方 MCP，没有保存凭证或原始用户响应；它不证明浏览器扩展已经安装或成功直连。

官方 OPTIONS 对本地网页与 GitHub Pages 来源返回 403，缺少允许该来源及认证头的 CORS 响应；认证 POST 在客户端成功没有改变此事实。静态网页不接受用户 Token，前端实时方案采用带官方域名 host 权限的本地扩展。服务使用方式待确认的具体条款见 [frontend-architecture.md](frontend-architecture.md)。
