# 纯前端扩展架构

2026-10-10。当前是本地 Manifest V3 原型；用户已安装并反馈修复后连接成功，官方域名访问权限已核对。尚未发布或获得 MCP 服务使用方式的专项确认。连接修复与验证范围见 [validation.md](validation.md)。

## 模块与运行方式

| 模块 | 职责 |
|---|---|
| `web/app.js` | 页面状态、输入、门店选择、领券确认、核价进度与转盘揭晓 |

| `web/account-storage.mjs` | 用户选择后的本机凭证 / 上次门店保存、读取和删除；可信上下文限制与跨页串行访问 |
| `web/local-record.mjs` | 麦当劳 / DeepSeek / 偏好三个独立记录的可信本机存储、原子更新与跨页锁 |
| `web/agent-view.mjs` / `web/agent.css` | AI 搭子设置、城市天气、推荐卡片与反馈管理 |
| `web/agent-prompts.mjs` / `web/meal-agent.mjs` | 个性提示词、最多两轮 Agent、已核价 ID / 理由校验与本地偏好排序 |
| `web/agent-memory.mjs` | 独立 DeepSeek key、偏好与显式反馈的限制、衰减和规范化 |
| `web/deepseek-client.mjs` / `web/agent-context.mjs` | Flash 官方 JSON API、城市天气、2026 假期与调休情境 |
| `web/store-search.mjs` | 营业状态 / 时段、地址列表脱敏、明确城市识别 |
| `web/meal-engine.mjs` | 套餐合法选项、券范围、整单比较、预算与有效期 |
| `web/order-history.mjs` | 主动读取历史、完成状态/日期/去重、热力图统计与最近主食 |
| `web/radar-view.mjs` / `web/radar.css` | 年度和近 12 周日历、日期餐单、常点餐品与导入按钮 |
| `web/launcher.js` | 点击扩展图标打开本地应用页，不接收 Token |
| `scripts/build_frontend.mjs` | 复制明确列出的前端文件与四份公开样本，生成扩展和静态页 |
| `scripts/serve_wheel.py` | 可选静态预览服务器，不含业务 API，不读取环境凭证 |

业务运行于扩展应用标签页，不需要业务后端。用户输入凭证后直接连接 `https://mcp.mcd.cn`；没有代理、账号收集服务或开发者云端数据存储。静态产物可以由普通静态服务器提供，但目前只支持样本体验。

## 普通网页为什么不能直连

本次对 localhost 与 GitHub Pages 来源检查官方 OPTIONS 预检，返回 HTTP 403，缺少允许这些来源及认证头的 CORS 响应；认证 POST 在本地客户端成功也不代表浏览器网页可以使用它。

Chrome 允许扩展应用页通过 `host_permissions` 发起跨域请求，说明见 [Chrome 官方网络请求文档](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。2.3.0 网络权限只含 `mcp.mcd.cn`、`api.deepseek.com`、`api.open-meteo.com` 和 `geocoding-api.open-meteo.com`，另申请 `storage` 用于本机保存；这是浏览器提供的权限模型，不能用来推断服务方授权。没有公共代理、`no-cors` 或关闭浏览器安全策略的方案。

## 凭证与个人数据

- Token 默认在应用页客户端私有内存中，提交后清空输入框。用户可自行勾选长期保存，用扩展专属 `storage.local` 保存 Token 和上次门店的编码、名称、城市；不保存输入的私人地址、联系人、券包、订单或报价。不使用 localStorage、IndexedDB、Cookie 或浏览器同步。[Chrome 存储文档](https://developer.chrome.com/docs/extensions/reference/api/storage)说明该存储在本机保留；本功能不承诺系统钥匙串或加密保险箱保护。
- 保存前设置 `TRUSTED_CONTEXTS`。读取、保存和删除按序执行；有 Web Locks 的浏览器按扩展 origin 协调多应用页，保存前核对旧凭证仍有效，避免旧页写回已撤销记录。一个页面删除或更新凭证，其他已连接页面清除旧账号；启动中的旧存储读结果不能恢复被删除的凭证。
- 页面退出中止在途请求并清空当前内存，保留已选择保存的记录；取消勾选立即删除长期凭证，但当前连接可继续用；主动断开同时清除当前连接和记录。MCP session、地址簿、券数据、历史订单与本次避开项每次页面退出都清空；2.3.0 的手写口味 / prompt 可显式保存，明确反馈有独立长期开关。异步旧结果不能恢复已断开的账号。401 / 403 清除无法认证的凭证；暂时网络失败保留记录，提供重试与手动清除入口。
- 初始化和工具请求使用官方域名，禁止跟随重定向；没有埋点、网络日志和第三方脚本。官方会收到执行用户查询或领券所需的数据。
- 个人券资产只用于范围校验与官方核价，展示只含名称、计数、条件与价格。打包文件只有公开脱敏样本。
- 历史由用户点击“读取我的历史”触发，仅查询 `order-list`；不查询订单详情。连接恢复不自动读取历史。订单 ID 在本次响应内去重，之后删除；页面只展示日期、状态、门店名称和餐品。没有保存或分享历史的功能。
- 前两天主食可手动勾选，或从返回记录按已知商品编码识别后主动导入；不会自动覆盖用户已选项，多人仍按全桌共同避开。未知日期不能当作没吃过，接口也没有分页参数。
- 地址读取是独立主动按钮，调用 `delivery-query-addresses`，仅取 `fullAddress` 供选择，不展示联系人、电话和地址 ID。选定地址填入位置关键词，明确城市才能查询到店门店。`query-nearby-stores` 只有城市 / 关键词参数，没有经纬度参数；没有 GPS。天气另用 Open-Meteo 检索城市中心，私人地址不进入天气或模型请求。营业状态只接受官方布尔值，缺失标未知，营业时段缺失不猜测；预约时段按接口完整展示，当前仍只选择即时到店取餐门店。

## AI 推荐与口味记忆

2.3.0 增加独立的 DeepSeek V4.1 Flash key 和偏好记录，保管方式沿用可信本机存储。刷新恢复配置但不调用 AI；推荐是用户主动按钮。推荐 Agent / 优化 Agent / 两轮协作可选，个性风格与 prompt 可编辑。价格和搭配由已有核价引擎提供，模型只选择已核价 ID，最多两轮并逐轮验证；不执行模型工具或业务写操作。明确反馈以 90 天半衰期减弱，长期保存默认关闭，可查看、忘掉和清空。细节及外部服务数据范围见 [meal-agents.md](meal-agents.md)。

## 用户动作与价格

连接、选择门店、准备餐单、读取历史和领券都由页面上的明确动作触发。已勾选长期保存后，刷新或重开恢复连接，并重新查询上次门店营业状态；没有后台定时查询。连接不会自动读取历史，查券不会自动领券。雷达不依赖选定门店；读取失败显示未完成，不生成“零订单”的假象。详细统计口径见 [order-radar.md](order-radar.md)。

领券需要确认“领取全部当前可领券”，发送一次 `auto-bind-coupons`，然后重读优惠信息、重新核价。写响应不明确时停止自动重复写，先由用户刷新券包核对。前端不提供下单、支付、取消或代他人领券。

核价只比较当前模板与可验证券范围；分页、方案上限、规则读取或报价失败会降低比较完整度。全部报价完成并按整顿预算过滤后才能转盘。五分钟是应用缓存上限，活动截止时间可提前结束；它不是官方价格保证。

## 参赛形式与尚待确认的调用范围

参赛形式依据：[官方活动规则](https://github.com/M-China/mcd-developer-innovation-challenge/blob/main/activityGuidelines.md)“参与方式”与“开发与发布项目”。本项目保持规定文件与实际接入说明；无需把扩展再套一个业务服务器。

活动“其他说明”同时引用 [MCP 服务规则](https://cdn.mcd.cn/cms/pages/MCPServerRules.html)。本次浏览器读取到规则版本为 2025-12-03：第二条限制凭证分享及非官方认证平台托管，第三条第二款限制批量、高频或自动化调用，第六条第二款涉及脚本、爬虫及自动化工具调用。

这些条款如何适用于比赛中用户主动操作的第三方本地扩展、多方案整单核价与官方一键领券工具，尚无明确确认。本机保管、用户主动按钮和浏览器 host 权限不能单独证明已满足所有服务条款。当前完成本地代码、构建、离线测试和官方只读查询；没有新增真实业务写操作或公开发布。

需要官方澄清的具体问题是：参赛者能否提供纯本地、无收费、用户自行填入 Token 的浏览器扩展，并在一次明确选餐动作中查询券范围、比较多份套餐核价；用户确认后调用官方一键领券是否属于允许的场景。此文记录问题，没有代用户联系官方。
