# AI 饭搭子、提示词与口味记忆

2.3.0，2026-10-10。当前实现为浏览器扩展内的可选择推荐工作流，支持 DeepSeek V4.1 Flash 和无模型调用的本地偏好排序。扩展源码与构建产物已准备；没有公开发布。

## 使用

1. 打开顶部“AI 搭子与记忆”，填写自己的 DeepSeek API key，点击“使用这个 key”。默认仅本页使用；可以单独勾选在本浏览器长期保存。填写时只做格式检查，首次点击 AI 推荐才向官方验证和请求模型。
2. 选择温柔饭搭子 / 精打细算派 / 惊喜探索家，以及合我口味 / 候选池尽量省钱 / 换个新口味。可选择单独推荐 Agent、单独优化 Agent，或推荐后再优化的两轮协作。
3. 写下口味偏好；需要时展开两个 Agent prompt，编辑并保存。保存的提示词与风格留在本机扩展中，密钥另存，不跨设备同步。
4. 连接麦当劳、选择营业中的门店、按人数 / 食量 / 预算核价，也可以使用明确标注的历史样本。选今天的心情。若希望参考天气，输入城市，查询后明确选择所在地区；同名地点不自动猜测。
5. 点击 AI 推荐或本地推荐。所有卡片沿用候选餐单的实际价格和内容，点击“就选这份”揭晓完整餐单。原转盘仍按剩余餐单等概率选择。
6. 明确点击“喜欢这份”或“以后少推荐”才更新口味反馈。长期记忆默认关闭；勾选并保存偏好后，反馈保存在本机，刷新可恢复。可查看、忘掉某种口味或清空反馈；关闭并保存清除长期反馈。手写偏好和 prompt 可单独编辑。

## 两个 Agent 与事实约束

调用顺序：官方核价和硬条件筛选 → 整理候选、偏好记忆和当地情境 → 推荐 Agent → 优化 Agent（选协作时）→ 程序检查每一轮输出 → 用户选择。

推荐 Agent 负责口味、心情和节令；优化 Agent 在同一批已核价候选内复核适配、价格与新鲜感，可以调整首选。优化范围覆盖成功报价并满足条件的当前候选，不能声称全菜单最优。每次最多两次模型调用，每轮 25 秒超时、1,200 个输出 token，不自动重试；用户可取消，模型错误保留手动重试和本地推荐入口。

- 不给模型传业务工具。McD Token、API key、联系人、私人地址、订单、门店编码和券资产 ID 不进入 prompt。AI 请求只携带公开候选餐单内容、核验金额与来源、预算 / 人数 / 食量、用户自己写的口味和 prompt、明确反馈摘要及已读城市天气 / 中国大陆节假日情境。
- 模型返回固定 JSON，最多三个不同候选 ID、有限的理由标签和风格枚举。程序拒绝未知或重复 ID、自创价格、额外字段、未有证据的天气 / 偏好理由、截断内容、工具调用及非 Flash 模型响应。卡片标题、份数和金额都从原核价报告渲染，模型不生成这些事实。
- “尽量省钱”通过程序把可选 ID 限制在整个当前候选池的最低核验价，模型只能在相同最低价的搭配间选择。其余目标按偏好、新鲜感、明确温度标签和相对价格生成最多 12 个候选，交给 Agent 复核。
- 自定义 prompt 只影响口味取舍与风格；预算、人数、食量和最近主食排除仍由程序执行。改变条件、门店、账号、prompt 或报价过期后取消在途推荐，丢弃旧结果。没有自动领券、下单或支付能力。

本地排序使用明确主食反馈：喜欢 +1、少推荐 −1.5，按 90 天半衰期减弱，每种主食的累计权重限制在 −3 到 +3。换口味目标提高没有反馈的主食权重；天气匹配和候选价格作为辅助。无法识别冷热的咖啡或饮品不假定温度，“热辣”不视为热饮。用户写的自由口味文本由 AI 理解，本地排序仅使用可解释的明确反馈。

## 本机记录

| 本机扩展记录 | 内容 | 保存时机 |
|---|---|---|
| `mcd-wheel.account.v1` | 麦当劳 Token、上次公开门店身份 | 原有独立 opt-in |
| `mcd-wheel.deepseek.v1` | DeepSeek API key | 勾选长期凭证并配置；格式检查后保存，首次推荐验证 |
| `mcd-wheel.agent-preferences.v1` | 风格、目标、Agent 模式、手写偏好、两个 prompt、天气开关、反馈开关与最多 80 条明确反馈 | 点击保存偏好；长期反馈开启后原子更新 |

每条反馈只含公开模板 ID、标题、已知主食编码 / 名称、反馈日期和 like / less。同一模板同一天重复点击会覆盖，不重复累加。反馈表示偏好，不表示已吃过。模型不能写记忆；真实雷达订单仍只在页面内存，未自动导入为长期记忆。样本体验的主动反馈同样属于口味反馈，不会当成真实消费。

三个记录共用可信上下文的 `storage.local` 访问器，读改写按记录键协调 Web Locks 和页内队列。凭证保存前核对旧记录；另一应用页撤销凭证后停用旧客户端，旧启动读取不能恢复已删除记录。记忆更新检查当前长期开关，不能写回另一页已撤销的反馈。取消 DeepSeek 凭证保存只删除长期记录，本页仍可用；主动停用同时中止请求。刷新仅恢复配置和反馈，不调用 AI，不自动收费。

凭证与记忆没有开发者服务器或浏览器同步；本机扩展存储不等同于系统加密保险箱。DeepSeek 会收到用户主动推荐所需的上述摘要，天气服务收到城市查询和选定城市中心坐标；不会发送精准私人地址。账户鉴权错误清除 DeepSeek 无效凭证，网络 / 限流 / 余额问题保留 key 并显示固定提示，不回显服务方原始错误。

## 天气与节令来源

- 天气使用 [Open-Meteo 城市检索](https://open-meteo.com/en/docs/geocoding-api) 和 [Forecast API](https://open-meteo.com/en/docs)；只检索中国大陆城市，明确选点后读取温度、体感和天气代码。30 分钟本页缓存，超过 90 分钟的观测不参与推荐，校验摄氏单位和数值。API 不可用时标记未知，继续按偏好与月份推荐。本原型使用公共非商业 API，商业发布应按服务方许可配置。
- 推荐日历使用 Asia/Shanghai 日期、月份和星期。2026 年七个假期及六个调休上班日来自 [国务院办公厅通知，国办发明电〔2025〕7号](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)。2026-10-10 正确标为调休上班日。其他年份不编造法定假期或农历日期，标记尚未收录；没有把普通节令当作麦当劳促销或折扣。
- 使用 [DeepSeek 官方模型文档](https://api-docs.deepseek.com/quick_start/pricing/)当前的 `deepseek-flash` → DeepSeek V4.1 Flash，固定 `https://api.deepseek.com/chat/completions`，非思考模式和 JSON Output；不请求第三方模型网关，不带 Cookie、不跟随重定向。麦当劳和 DeepSeek 的 Authorization 头分别由各自客户端生成。

静态体验页只提供本地推荐与本页偏好，不接受或保存任何 key，不读取天气。Chrome 已实际完成保存配置的重载恢复、麦当劳实时核价、城市天气和 DeepSeek 两轮推荐；非空长期反馈与整个浏览器关闭后的恢复仍需分别验收。模拟链路、边界校验和实际浏览器证据见 [validation.md](validation.md)。
